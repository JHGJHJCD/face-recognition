# בודק באגים — נקודה אחת, עד הסוף

מטרה: לקחת **נקודה אחת** בתוכנה (מסך / כפתור / זרימה / חישוב) ולחפור עליה עמוק עד שבטוחים שאין בה באגים —
ואת מה שנמצא **לתקן מיד**, לאמת ולשחרר. עומק על פני רוחב: לא סקירה כללית של כל התוכנה.

הנקודה לבדיקה: **$ARGUMENTS**

## שלב 0 — מה בודקים
- `$ARGUMENTS` ריק/עמום → **שאלה ממוקדת אחת** (AskUserQuestion, עברית מדוברת, "(מומלץ)") עם 3–4 נקודות
  קונקרטיות לבחירה (למשל: "רישום אדם חדש (מצלמה / תמונות / סרטון)", "זיהוי חי והתרעת לא-מוכר", "בדיקת סרטון
  מקישור יוטיוב", "יומן נוכחות וייצוא", "גיבוי/שחזור ועדכון תוכנה"). **לא לסרוק את כל הפרויקט כדי להחליט.**
- קרא קודם את `CLAUDE.md` של הפרויקט (מבנה, מלכודות, "נמדד ונפסל") — הרבה תשובות כבר שם.
- הגדר במשפט אחד **מה ההבטחה** של הנקודה ("שם שהוזן בחלון נשמר בדיוק כפי שהוקלד, פעם אחת, והאדם מזוהה מעכשיו").
  כל באג = הפרה של ההבטחה הזו.

## שלב 1 — מיפוי (קריאה בלבד)
1. מצא את נקודת-הכניסה — בדרך כלל ב-`webui/static/app.js` (כפתור → `act("…")`) → `webui/backend.py` (ה-API) →
   `core/` (`db.py` / `engine.py` / `live.py` / `jobs.py` / `ai.py`) — וקרא כל שלב **במלואו** עד ה-DB / הקובץ / הרשת.
2. `grep` לכל מי ש**קורא** לאותה פונקציה (backend, live, jobs, tests, dev, main_classic) — באג חי לפעמים אצל הקורא.
3. רשום: קלטים (משתמש / מצלמה / קובץ / יוטיוב / Gemini), פלטים, מצב שנכתב (`data/faces.db`, `settings.json`,
   גלריה בזיכרון, `unknown/`), והנחות סמויות ("יש מנוע", "המצלמה פתוחה", "התוצאה מהסריקה הקודמת עוד תקפה").
4. `git log -S` / CLAUDE.md — אם כבר תוקנו כאן באגים, לא להחזיר אותם ולדעת איפה הקוד שביר.

## שלב 2 — ציד (לעבור על **כל** הרשימה, לכתוב ממצא או "נקי" לכל סעיף)
- **ערכי-קצה:** שם ריק / רווחים בלבד / גרשיים / אימוג'י / אותיות לטיניות · אותו שם פעמיים (מיזוג שקט!) · תאריך לידה
  עתידי או בפורמט אחר · תיקייה ריקה / 10,000 תמונות · סרטון בלי פנים / פנים אחת בלבד / 50 אנשים.
- **מנועים ומצלמה:** פעולה לפני שהמנועים נטענו (`need_engine`) · מצלמה שנפלה באמצע רישום · GPU שנפל ל-CPU ·
  מודל זהות אחר (`model` בטבלת samples) · סף זיהוי 0 / 1.
- **מצב וזמן:** לחיצה כפולה · ביטול/עצירה באמצע (Gemini באמצע קריאה!) · סגירת התוכנה באמצע כתיבה · `poll` שמרנדר
  מחדש מסך בזמן שחלון פתוח · תוצאה ישנה (`video_result`, `clusters`, `S.sel*`) שנשארה אחרי סריקה חדשה · חצות ·
  שעון ישראל.
- **חוטים ו-Qt:** נגיעה ב-DB בלי `db.lock` · ווידג'ט/QWebEngineView מחוץ לחוט הראשי (`in_main`) · עבודה כבדה
  **בחוט הראשי** (`view.grab`, JPEG, DB) שמקפיאה הקלדה · signal אחרי שה-worker מת · `stop_flag` שלא נבדק בלולאה.
- **ממשק HTML:** `innerHTML` שנכתב מחדש כל poll ומאבד פוקוס/בחירה · `[hidden]` על `.btn` · גלילה (`#app` 100vh) ·
  `esc()` חסר ב-HTML שמגיע מנתונים · `backdrop-filter` מעל canvas חי · Ctrl+מספר שנתפס בזמן הקלדה בחלון.
- **נתונים:** כתיבה חלקית בלי טרנזקציה · חריגה באמצע לולאה · מחיקה בלי גיבוי · מיגרציה על DB ישן (`ALTER TABLE`)
  · `reload_gallery` שלא נקרא אחרי כתיבה · thumb `NULL`.
- **רשת/AI:** נטפרי 418 · timeout · מפתח Gemini חסום (429) · מודל מושבת (503) · JSON לא תקין מ-Gemini ·
  עדכון תוכנה שנכשל באמצע הורדה.
- **שגיאות:** `except` רחב שבולע · הודעה גולמית באנגלית למשתמש · `crash_log.txt` שלא נכתב.
- **עקביות:** אותו חישוב בשני מקומות (גיל מתאריך לידה מול FairFace, סיכום נוכחות במסך מול אקסל) · מונה שלא תואם
  לרשימה · CLAUDE.md שסותר את הקוד.

לכל חשד: **לא להסתפק בקריאה — להריץ.** סקריפט קצר על DB זמני (`tempfile`, **לעולם לא `data/faces.db` האמיתי**,
בלי Gemini אמיתי אלא אם זה הנושא) שמשחזר את התרחיש; ל-API בלי חלון — `dev/probe_api.py`; להקלדה/קיפאון —
`dev/probe_typing.py`; לסרטון — `dev/probe_video.py`. חשד שלא שוחזר = לא באג; לרשום כ"נבדק, תקין".

## שלב 3 — תיקון מיידי
לכל באג שהוכח, לפי הסדר **שלמות נתונים → דיוק הזיהוי → יציבות → חוויית משתמש → איכות קוד**:
1. **בדיקה שנכשלת קודם** — ב-`tests/test_pipeline.py` / `test_upgrade.py` / `test_video_check.py` (באותו סגנון) ולראות אותה נכשלת.
2. תיקון **בשורש** (ב-`core/` כשזו לוגיקה, לא פלסטר ב-`app.js`); לא לשבור תאימות לאחור, לא לשנות עמודות DB בלי מיגרציה.
3. לראות את הבדיקה עוברת. לחפש **את אותו דפוס-באג במקומות אחרים** (`grep`) ולתקן גם שם.
4. מה **לא** מתקנים לבד: הכרעה של יהודה שכתובה ב-CLAUDE.md ("הכרעת יהודה"), או שני פירושים סבירים להתנהגות —
   לאסוף ל**סבב שאלות אחד** בסוף (AskUserQuestion), ובינתיים להמשיך בשאר.

## שלב 4 — אימות ושחרור
1. הבדיקות הרלוונטיות (Python **3.12** בלבד: `...\Python312\python.exe tests\test_X.py`).
2. נגעת ב-UI → `main.py --shot <תיקייה קיימת>` (או `--shot-video`) ואימות התמונה דרך `gemini_task.py -f <png>`
   (**לא לקרוא PNG לצ'אט** — נטפרי). שני צילומים זהים בגודל = מסך שנתקע.
3. תיעוד: מלכודת חדשה → `CLAUDE.md` "מלכודות ידועות"; שינוי התנהגות → הסעיף המתאים ב-CLAUDE.md.
4. תוקן משהו → שחרור לפי "בנייה ושחרור" ב-CLAUDE.md (`version.py` → build → `app.zip` → commit/push → release,
   **בלי קרדיט Claude**), ברקע עם עדכון קצר. לא נמצא כלום → לא משחררים; נוספו בדיקות → commit בלבד.
5. סיכום קצר ליהודה בעברית פשוטה: מה נבדק, **מה היה קורה לו בפועל** בכל באג, מה תוקן, ומה נשאר לשאלה.
